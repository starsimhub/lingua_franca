# Webapp

A tool for viewing the originals in `models` side by side with their translations, with diff-style markup and highlighting.

## Purpose

Reading a translation next to its original is the fastest way to see whether the lingua franca is doing its job. This webapp makes that comparison the default view: pick a model, see the original framework code on the left and the lingua franca version on the right, with the correspondence between them made visible.

## Intended behavior

- **Model picker**: browse the corpus by framework, paradigm, or feature exercised
- **Side-by-side panes**: original on the left, translation on the right, with syntax highlighting for both languages
- **Diff-style markup**: highlight what corresponds, what was simplified, and what gets uglier
- **Aligned scrolling**: keep semantically corresponding regions in view together, rather than aligning by line number
- **Annotations**: surface the model's commentary inline, anchored to the relevant region
- **Results comparison**: where reference outputs exist, show the original's and the translation's results together
- **Benchmark table**: for each model, lines of code and run time for the original and the translation, so the "no more lines, no more time" test is visible at a glance across the whole corpus. Its numbers are regenerated by [the benchmark](../benchmark/README.md)

Because the two sides are different languages, a plain textual diff will not be meaningful. The alignment needs to come from the translation declaring the correspondence between its blocks and the original's — worth settling on a format for that early, since it affects how vignettes are written.

## Status

A first version is part of the project's website, which is built with [Quarto](https://quarto.org) from the Markdown files in this repository:

- `scripts/build.py` reads each model's `meta.yaml`, original source, translation, and `README.md`, and writes the Markdown for the comparison page and the benchmark table. The pages that show them (`webapp/index.qmd`, and the table on the home and models pages) call it as they are rendered, so there are no generated files to keep up to date.
- `_picker.html` is the script that shows one model at a time.
- The model picker, side-by-side panes, syntax highlighting, the model's notes, and the benchmark table are done. Diff-style markup, aligned scrolling, anchored annotations, and the results comparison are not: they wait on a format for a vignette to declare which of its blocks corresponds to which of the original's.

To build the site, run `quarto render docs` from the root folder (it needs `sciris` and `jupyter`), or `quarto preview docs` to see it while editing. A new model also needs its two `README.md` files added to the `render` and `sidebar` lists in `_quarto.yml`.

## Relationship to other folders

- Reads its content from `models`.
- Makes gaps in `design` visible by showing where translations lose or add meaning.
